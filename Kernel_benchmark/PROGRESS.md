## Known Issues
1. **Simulation data instability at final timestep**: Several benchmarks (advbspi, diver2d, advs, buoywsi, vbcv) fail validation because the dumped data contains extreme values (Infinity, NaN). This is because:
   - Data was dumped at simulation's final call count (e.g., 28800 for advbspi)
   - The simulation may have become numerically unstable by that point
   - **Solution A**: Change DUMP_TARGET in Src/*.f90 to earlier timestep (e.g., 1000)
   - **Solution B**: Generate synthetic test data like diver3d, copy3d, bcycle do

2. **params.txt format mismatch**: Dump module writes `key = value` format. Some benchmark programs were updated to parse this format (advbspi, diver2d). Others may need similar updates.

3. **Working benchmarks use synthetic data**: The 7 verified working benchmarks (bc4news, bcycle, copy3d, diagni, disptke, diver3d, vbcu) use either:
   - Synthetic test data generated by generate_data.f90
   - Small test grids (100x100x64) instead of full simulation grids (899x899x128)
