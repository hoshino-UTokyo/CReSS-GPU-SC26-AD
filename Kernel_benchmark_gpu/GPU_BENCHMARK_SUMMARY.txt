4. FAIL 7件の詳細
================================================================================

【A. 浮動小数点精度の問題（5件）】
   → GPU移植自体は正しいが、CPU/GPU間のFPU実装差による

   1. 041_bruntv_s_bruntv
      - 症状: 境界条件 t <= tlow (233.16K) の判定差
      - 原因: 1 ULP差で異なる分岐に入り、潜熱項の加算有無が変わる
      - エラー率: 820%

   2. 056_cloudcov_s_cloudcov
      - 症状: cdm出力に極端に大きな相対誤差
      - 原因: GPU=1.9e-8 vs Ref=0.0（ゼロ近傍の相対誤差）
      - エラー率: 1.9e12

   3. 087_disptke_s_disptke
      - 症状: Catastrophic cancellation（壊滅的キャンセル）
      - 原因: exp, log, sqrt のGPU実装差がほぼ等しい値の引き算で増幅
      - エラー率: 66.7%

   4. 296_siadjst_s_siadjst
      - 症状: 境界条件 qi > dqi の判定差
      - 原因: 飽和調整計算で1 ULP差により異なる分岐
      - エラー率: 0.73%

   5. 320_swadjst_s_swadjst
      - 症状: 境界条件 qc > dqc の判定差
      - 原因: 飽和調整の2回反復計算でdqc計算のわずかな差
      - エラー率: 133%

【B. データ生成の問題（2件）】
   → ベンチマークデータ自体に欠陥あり（CPU版もFAIL）

   6. 042_bulksfc_s_bulksfc
      - 症状: 100%エラー（1,612,808 errors）
      - 原因: params.txtに必要なパラメータ欠損
        (wkappa, prnumg, prnumw, icz0m, icz0h, rmg, rms, rhg, rhs, oned3, cc)
      - 対策: ダンプデータ再生成が必要

   7. 239_phycood_s_phycood_sec3
      - 症状: 12500エラー（103,671,720 errors）
      - 原因: params.txtのパラメータ値不正
        (nkm1=0, nkm2=0 ← 本来 nk-1=127, nk-2=126)
      - 対策: ダンプデータ再生成が必要

6. 技術方針
================================================================================

【プログラミングモデル】
  - OpenACC を使用
  - !$acc kernels + !$acc loop independent

【メモリ管理】
  - Unified Memory (-gpu=managed) でデータ転送を自動化
  - 明示的な !$acc data ディレクティブは使用しない

【コンパイラ設定】
  FC = nvfortran
  FFLAGS = -O3 -acc -gpu=managed -mp -Mbyteswapio -Minfo=accel

【タイミング】
  - omp_get_wtime() を使用
  - GPU同期には !$acc wait を使用

================================================================================
7. 残課題
================================================================================

1. 浮動小数点精度問題（5件）
   - CPU/GPU間のFPU実装差が原因
   - 対策オプション:
     a) -Kieee または -gpu=nofma でIEEE準拠モード（性能低下）
     b) tolerance緩和（1e-5 → 1e-3）（真のバグ見逃しリスク）
     c) 境界条件にイプシロン余裕追加（物理的意味が変わる可能性）
   - 現状: 上記対策は未採用

2. データ再生成が必要（2件）
   - 042_bulksfc_s_bulksfc
   - 239_phycood_s_phycood_sec3

3. 残りカーネルのポーティング
   - 150件（データあり）のうち、未ポーティング分を継続
