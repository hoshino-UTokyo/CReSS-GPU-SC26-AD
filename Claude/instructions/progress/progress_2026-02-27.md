# Progress Report: 2026-02-27

## Phase 5: Simulation Integration - Bug Fix Session

### Root Cause Analysis

Systematic comparison of GPU vs CPU code across all Src files (179-364 range) identified critical bugs in boundary condition kernels:

#### Bug 1: phvuvw.f90 (Kernel 235) - Phase Speed Calculation [CRITICAL]
- **Problem**: GPU code only had constant phase speed assignment (bc=7), missing:
  1. `exbvar`/`exbopt` guard conditions
  2. `mfcopt` clamping (max/min with map factor arrays)
  3. `dtsdb` scaling (time step ratio: small/large step)
- **Impact**: With exbvar='--x---xx', w-component phase speed was unclamped and unscaled
- **Fix**: Complete rewrite of GPU block with all 12 boundary-component combinations (u/v/w x west/east/south/north), each with proper guard, clamping, and scaling
- **Additional fix**: Loop bound corrections for w component (all nk-2 changed to nk-1) and v west (nk-1 changed to nk-2)

#### Bug 2: phvbcuvw.f90 (Kernel 233) - Differential Phase Speed [CRITICAL]
- **Problem**: Same as phvuvw - GPU code only had constant assignment, missing exbvar guards, clamping, and dtsdb scaling
- **Impact**: With exbvar(1:1)='-' and exbvar(2:2)='-', u and v differential phase speeds were unclamped and unscaled
- **Fix**: Complete rewrite of GPU block with all 12 boundary-component combinations with correct exbvar guards ('-' or '-/+'), clamping, and dtsdb scaling

#### Bug 3: lbcw.f90 (Kernel 190) - w-velocity Boundary Conditions [MODERATE]
- **Problem**: All 8 GPU loop upper bounds were `nk-2` instead of `nk-1`
- **Impact**: w-velocity boundary conditions missing one layer (w is on cell faces, needs nk-1)
- **Fix**: Changed all `do k=2,nk-2` to `do k=2,nk-1` in GPU block

### Bug Origin

Confirmed that bugs originated in **Kernel_benchmark_gpu** (Phase 4). The benchmark implementations for 233 and 235 only had the constant phase speed assignment code, without the post-processing steps (clamping, scaling). Variables like `dtsdb`, `rmf8u`, `rmf8v` were loaded but never used. The benchmarks PASSED because validation only checked the pre-clamping values, or reference data was generated from the same incomplete code. When Src/ files were populated from benchmarks during Phase 5 integration, the bugs were carried over.
