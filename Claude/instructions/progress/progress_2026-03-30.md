## Completed Tasks

### 1. Kernel_benchmark_gpu_opt ディレクトリ作成
- `Kernel_benchmark_gpu` からコピー
- 壊れたシンボリックリンクを確認（初期化系カーネル8件、最適化対象外）

### 2. pgrad 最適化 (GPU時間 #1, 11.0%) — **1.80x 高速化**
- **最適化**: tmp3 中間配列の完全インライン化
- divopt==2 パス: `tmp3 = pp + divcv*jcb*tmp1` → `tmp3 = pp + divch*tmp1/jcb` → `tmp3 = jcb*tmp3` の3ステップを排除
- wpg/upg/vpg を pp, jcb, tmp1 から直接計算
- 6カーネル → 2カーネルに削減
- **結果**: 4.026ms → 2.240ms, Validation PASSED (誤差ゼロ)

### 3. stepwi 最適化 (GPU時間 #2, 11.0%) — **1.21x 高速化**
- **最適化**: Step 2 の tmp1/tmp2 中間配列をスカラー変数に置換 + collapse(3) + カーネル融合
- 5カーネル → 2カーネルに削減
- **結果**: 3.885ms → 3.210ms, Validation PASSED

### 4. diver3d 最適化 (GPU時間 #4, 7.7%) — 微小改善
- **最適化**: 全中間配列(tmp1/tmp2/tmp3)のインライン化 + collapse(3)
- 4カーネル → 1カーネルに削減
- **結果**: 2.740ms → 2.731ms (-0.3%), 理論上のBW削減が実効改善に結びつかず
- **原因**: ステンシルアクセスパターンで7配列×2点を読むためL2キャッシュ圧迫

### 5. advs 最適化 (GPU時間 #7, 5.3%) — 微小改善
- **最適化**: 独立カーネルの融合（2次精度フラックス3→1ブロック、4次精度2→1ブロック等）
- 10カーネル → 7カーネルに削減
- **結果**: 6.866ms → 6.832ms (-0.5%)
- **原因**: ステップ間のデータ依存関係が強く、融合余地が限定的

### 6. その他のカーネル

- **buoywsi**: 1.499→1.489ms (-0.7%), collapse(3) + 融合

- **steppi**: 既に単一カーネル、変更なし

## Blockers / Issues
- **diver3d**: 理論上の帯域削減がパフォーマンスに反映されない。L2キャッシュ圧迫が原因と推定。共有メモリタイリングが必要だがOpenACC kernelsでは困難。

- **smoo4s**: ベースラインでvalidation FAILED（tolerance=1e-2境界ケース）
